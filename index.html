02 / HOW IT WORKS

保存するものを、迷わない。

本文の正本と、見た目の設定を分けて扱います。

A

本文は、元の場所へ

予定・宿の案内・雪遊びの説明・持ち物は、旅行データの元の項目を更新。表示用の二重管理を増やしません。

trip.yaml / 既存の各項目
B

見た目は、この旅行に

文字サイズ、行間、余白、時刻欄の幅。限定した数値設定とUI固有の文言を、旅行ごとに保持します。

presentation.compact
C

確認してから、保存

変更前後を確認して明示保存。外部の変更を見つけたら停止。文言の編集日と事実の確認日は区別します。

差分確認 / 競合検出 / 編集記録
ローカル編集→差分確認・保存→検証・PR→devで確認→OK後に本番

03 / EDITING BOUNDARIES

文言を整える範囲。

このモックは、4セクションの代表的な文言で操作を試せます。すべての項目の編集機能を実装したものではありません。

セクション初版の編集候補読み取り専用
予定見出し・通常の補足文時刻・日付・状態・夕食の生成文
宿チェックイン説明・アメニティ案内・装飾文予約状態・施設名・住所・URL
雪遊び説明・見出し・導入文料金・対象年齢・営業状態・出典
持ち物既存の品目・補足・導入文初版では追加削除・並べ替えは対象外

このレポートで試せること／実装時に検証すること

試せること文言選択と編集、6つの見た目設定、4段階の実幅プレビュー、文字拡大、Undo/Redo、差分と保存結果のシミュレーション。

まだ実装していないことYAML書込み、再起動後の復元、実ファイルの競合検出・復旧、認証付きローカル編集API。下の保存画面では成功・競合・失敗を模擬表示できます。
